# Trip Planner 页面规则

本页继承 `../MASTER.md`，以下规则优先。

## 主要任务路径

`搜索地点 -> 加入地点库 -> 排入今天 -> 生成路线 -> 保存行程`

桌面端让这条路径在一个工作台中可见。手机端不并排压缩，而是让地图、地点、行程在同一抽屉中切换。

## 桌面端

- 左侧窄导航只提供真实入口：旅行列表、行程、地点、地图、已保存行程。
- 地点库用于选择和加入，不展示虚构票价、照片或收藏功能。
- 时间线突出开始时间、地点名称、停留时间与路线段。
- 地图与卡片双向联动，选中的地点在地图和详情卡中保持同步。

## 移动端

- 顶部保留旅行名、日期和 AI 规划，不使用两行导航。
- 底部抽屉有“今日行程、地点库、地图”三个明确入口。
- “地图”折叠抽屉，只保留标签条，保证地图可完整操作。
- 生成路线、保存行程和路线类型始终位于抽屉底部，不依赖滚动到行程末尾。
- 超长地点名、地址与日期信息允许多行折行；小于 420px 时主要和次要操作分为两行。

## 状态要求

- 搜索、地点库、路线和保存继续使用当前加载、空和错误状态。
- 路线生成反馈仅由业务请求状态驱动。Rive 加载失败时仍可正常生成路线。
- 路线失败显示现有 Toast 文案，不在 UI 层篡改接口错误或业务状态。
